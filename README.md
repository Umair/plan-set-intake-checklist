# Plan set intake checklist

An open checklist for checking a construction plan set **before** you start the takeoff. It catches the problems that are cheap to fix on day one and expensive to find on bid day: missing sheets, wrong scales, unread legends, schedules that disagree with the plans, and addenda nobody logged.

Fork it, cut what does not apply to your trade, add what does, and run it on every bid.

## How to use it

1. Copy this file into your bid folder, or open it as an issue in your own fork and tick boxes as you go.
2. Work top to bottom. The order matters: you cannot check scales on sheets you do not have.
3. Every box you cannot tick becomes one of three things: a question to the design team, a clarification in your proposal, or a note on the sheet so nobody measures it blind.

## 1. Package and sheet index

- [ ] The sheet index matches the sheets received: same count, same numbers, same titles.
- [ ] Every discipline your scope touches is in the set (architectural, structural, civil, plumbing, mechanical, electrical, fire protection, landscape).
- [ ] Every sheet's title block shows the current issue date and revision. Sheets from different issues are flagged.
- [ ] The specifications (project manual) were received, and the sections for your trade are identified.
- [ ] Bid documents received: invitation to bid, bid form, instructions, any pre-bid meeting or site walk dates.
- [ ] File quality checked: vector PDF or scanned image, text searchable or not, pages rotated the right way.

## 2. Scales

- [ ] Each view's scale is noted. One sheet can carry several scales (plan, enlarged plan, details).
- [ ] Graphic scale bars are present, and one bar per sheet measures what it says.
- [ ] One known dimension per sheet measured against the stated scale. If it disagrees, stop and find out why.
- [ ] Sheets received at reduced size (half-size sets) are identified, with the reduction noted so nobody measures at the printed scale.
- [ ] Views marked NTS (not to scale) are flagged and not measured.
- [ ] Metric sheets, if any, are identified, with the units the estimate will use.

## 3. Legends, abbreviations and notes

- [ ] The symbol legend for each discipline was read before any counting. Project-specific symbols and variants are noted.
- [ ] The abbreviation list was read; unfamiliar abbreviations are looked up, not guessed.
- [ ] General notes read for every discipline you price. Notes that change materials or methods are copied into your estimate notes.
- [ ] Keyed notes read: every tag on the plans has a note, every note has at least one tag.
- [ ] Responsibility notes found and listed: "by others", "owner furnished, contractor installed", "existing to remain", "relocate".

## 4. Schedules

- [ ] Every schedule your scope uses is present: doors, windows, finishes, fixtures, equipment, panels, plumbing fixtures.
- [ ] Tags on the plans match rows in the schedules, both ways: no tag without a row, no row without a tag.
- [ ] Quantities written in schedules (where given) agree with what the plans show.
- [ ] Equipment on other disciplines' schedules that affects your scope is noted (connections, supports, openings).

## 5. Addenda and revisions log

- [ ] Every addendum and bulletin is logged as it arrives, in a table like this one:

- [ ] Each reissued sheet was compared with the version you priced, including areas outside the revision clouds.
- [ ] Every logged change lands on an estimate line, or is marked "no impact" with a reason.

## 6. Questions and clarifications

- [ ] The question deadline for the bid is noted, and questions are sent before it.
- [ ] Open questions with no answer by bid day are written as clarifications in the proposal, one assumption per line.
- [ ] Existing conditions you could not verify are listed as assumptions.

## 7. Before you start the takeoff

- [ ] The set you are taking off from is saved as a frozen copy, with revision numbers, so later changes can be measured against it.
- [ ] Everyone working the bid is using the same set.

## Contributing

Pull requests are welcome, especially trade-specific sections (electrical, plumbing, drywall and framing, concrete, sitework) and checks from your own lost bids. Keep items short, start each one with the thing to check, and avoid naming products. Open an issue if you are not sure where something belongs.
